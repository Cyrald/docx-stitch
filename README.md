# docx-stitch

[![PyPI](https://img.shields.io/pypi/v/docx-stitch.svg)](https://pypi.org/project/docx-stitch/)
[![Python](https://img.shields.io/pypi/pyversions/docx-stitch.svg)](https://pypi.org/project/docx-stitch/)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

docx-stitch склеивает любое количество документов `.docx` в один.
Единственная зависимость — `lxml`.

## Возможности

- **N документов в любом порядке**, один и тот же файл можно вставить несколько раз.
- **Выбор главного документа** (`base`). Его настройки, тема, docDefaults,
  встроенные стили (Heading 1, TOC 1, Hyperlink…) и колонтитулы служат основой
  результата. Главным можно сделать документ в любой позиции, порядок текста от этого не меняется.
- **Тип стыка между документами**: разрыв раздела (`nextPage`, `continuous`,
  `evenPage`, `oddPage`, `nextColumn`), обычный разрыв страницы (`page`) или
  стык без разрыва (`none`). Задаётся для всех документов сразу или для каждого отдельно.
- **Разделитель между документами**: любой текст (`"* * *"`, `"—"`, несколько
  строк через `\n`) со стилем из главного документа и нужным выравниванием.
- **Два режима стилей**:
  - `isolate` (по умолчанию). Каждый документ выглядит точно так же, как в своём файле.
    Его стили копируются под уникальными id (`_doc2_Heading1`, «doc2: Heading 1»),
    а docDefaults главного документа на него не влияют.
  - `base`. Одноимённые стили берутся из главного документа, недостающие копируются.
    Получается то же, что при вставке в Word с параметром «Использовать стили конечного фрагмента».
- **Колонтитулы, поля, ориентация и размер страницы** сохраняются у каждого документа,
  потому что каждый становится отдельным разделом.
- **Нумерация страниц** может начинаться заново с любого числа у любого документа.
- **Исключение из оглавления** (`exclude_from_toc`) убирает уровни структуры, и абзацы
  документа не попадают ни в оглавление, ни в область навигации.
- **Корректный перенос содержимого**: изображения, нумерованные и маркированные списки
  (у каждого документа своя нумерация), сноски и концевые сноски, закладки и ссылки на них
  (REF, PAGEREF, HYPERLINK), шрифты, пространства имён расширений (w14, w15…),
  гиперссылки. Id рисунков, закладок, списков, сносок и связей перенумеровываются.
- **Ввод и вывод**: пути, `bytes`, бинарные потоки. Результат можно получить как `bytes`.
- **Интерфейсы**: функция `stitch()`, построитель `Stitcher`, CLI `docx-stitch`
  и `python -m docx_stitch`.
- Аннотации типов (`py.typed`), Python 3.10+.

## Установка

```bash
pip install docx-stitch
```

## Быстрый старт

### Python

```python
from docx_stitch import stitch


stitch(
    ["title.docx", "body.docx", "appendix.docx"],
    "report.docx",
    base=1,
)
```

### Командная строка

```bash
docx-stitch title.docx body.docx appendix.docx -o report.docx --base 2
```

В CLI документы нумеруются с 1, в Python API — с 0.

## Python API

### `stitch(documents, output=None, **options)`

```python
from docx_stitch import stitch, Source

stitch(
    [
        Source("title.docx", exclude_from_toc=True, break_after="nextPage"),
        "body.docx",
        Source("appendix.docx", page_number_start=1, style_mode="base"),
    ],
    "report.docx",
    base=1,                     # главный документ (можно отрицательный: -1 — последний)
    break_type="nextPage",      # стык по умолчанию
    style_mode="isolate",       # режим стилей по умолчанию
    separator=None,             # текст между документами
    separator_style=None,       # id или имя стиля главного документа
    separator_alignment="center",
    keep_headers_footers=True,
    exclude_from_toc=False,
)
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `documents` | — | Документы в итоговом порядке: путь, `bytes`, бинарный поток или `Source` |
| `output` | `None` | Путь или бинарный поток. Если `None`, функция возвращает `bytes` |
| `base` | `0` | Индекс главного документа |
| `break_type` | `"nextPage"` | Стык между документами, см. таблицу ниже |
| `style_mode` | `"isolate"` | `"isolate"` или `"base"` |
| `separator` | `None` | Текст между документами; `\n` создаёт несколько абзацев |
| `separator_style` | `None` | Стиль разделителя из главного документа (id или отображаемое имя) |
| `separator_alignment` | `"center"` | `left`, `center`, `right`, `both` |
| `keep_headers_footers` | `True` | Переносить колонтитулы присоединяемых документов |
| `exclude_from_toc` | `False` | Убрать присоединяемые документы из оглавления |

#### Типы стыка

| Значение | Что получится |
|---|---|
| `nextPage` | Разрыв раздела, следующий документ начинается с новой страницы |
| `continuous` | Разрыв раздела на той же странице |
| `evenPage` / `oddPage` | Разрыв раздела, следующий документ начинается с чётной или нечётной страницы |
| `nextColumn` | Разрыв раздела со следующей колонки |
| `page` | Обычный разрыв страницы **без** нового раздела. Последний раздел документа сливается со следующим и берёт его поля и колонтитулы |
| `none` | Без разрыва, текст идёт подряд. Разделы сливаются так же, как при `page` |

С разрывами раздела каждый документ сохраняет свои поля, ориентацию,
колонтитулы и колонки.

### `Source`: параметры отдельного документа

```python
Source(
    document,                    # путь / bytes / поток
    break_after=None,            # стык ПОСЛЕ этого документа
    style_mode=None,             # "isolate" | "base"
    style_prefix=None,           # префикс id стилей, по умолчанию "_docN_"
    keep_headers_footers=None,
    exclude_from_toc=None,
    page_number_start=None,      # начать нумерацию страниц с этого числа
    name=None,                   # имя для сообщений журнала
)
```

Поля со значением `None` берутся из общих параметров. У последнего документа
`break_after` не используется. Параметры стилей к главному документу не применяются.

### `Stitcher`

Удобен, когда список документов собирается постепенно:

```python
from docx_stitch import Stitcher

s = Stitcher(break_type="nextPage", separator="* * *")
s.add("chapter1.docx")
s.add("chapter2.docx", base=True)          # главный документ
s.add("appendix.docx", page_number_start=1)
s.prepend("title.docx", exclude_from_toc=True, break_after="nextPage")

s.move(3, 1)       # переставить документ
s.remove(2)        # убрать документ
s.set_base(0)      # сменить главный документ

s.save("book.docx")      # в файл или поток
data = s.to_bytes()      # или в память
```

`Stitcher` запоминает главный документ по ссылке, а не по номеру. После
`insert`, `prepend`, `move` и `remove` главным остаётся тот же документ.

### Работа в памяти

```python
import io
from docx_stitch import stitch

with open("a.docx", "rb") as a:
    data: bytes = stitch([a, b_bytes, "c.docx"])     # без output — вернёт bytes

buf = io.BytesIO()
stitch(["a.docx", "b.docx"], buf)                    # запись в поток
```

### Ошибки и журнал

Все ошибки входных данных и параметров вызывают `docx_stitch.StitchError`,
подкласс `ValueError`. Сообщения рассчитаны на конечного пользователя.

Предупреждения пишутся в логгер `docx_stitch`. Например, о неподдерживаемых
объектах (диаграммы, OLE, SmartArt) и примечаниях Word, которые не переносятся:

```python
import logging
logging.getLogger("docx_stitch").setLevel(logging.ERROR)   # выключить предупреждения
```

## Командная строка

```text
docx-stitch FILE [FILE ...] -o OUTPUT [параметры]
python -m docx_stitch FILE [FILE ...] -o OUTPUT [параметры]
```

| Параметр | Описание |
|---|---|
| `-o, --output FILE` | Итоговый файл (обязательно) |
| `-b, --base N` | Главный документ, по умолчанию `1` |
| `--break TYPE` | Стык по умолчанию: `nextPage`, `continuous`, `evenPage`, `oddPage`, `nextColumn`, `page`, `none` |
| `--break-after N=TYPE` | Стык после документа N (можно повторять) |
| `--style-mode {isolate,base}` | Режим стилей по умолчанию |
| `--style-mode-for N=MODE` | Режим стилей для документа N |
| `--prefix N=PREFIX` | Префикс id стилей документа N |
| `--separator TEXT` | Текст между документами (`\n` разделяет строки) |
| `--separator-style STYLE` | Стиль разделителя |
| `--separator-align {left,center,right,both}` | Выравнивание разделителя |
| `--no-headers-footers` | Не переносить колонтитулы присоединяемых документов |
| `--exclude-from-toc` | Убрать все присоединяемые документы из оглавления |
| `--exclude-from-toc-for N` | Убрать документ N из оглавления |
| `--page-start N=START` | Нумерация страниц документа N начинается с START |
| `-f, --force` | Перезаписать существующий файл |
| `-v` / `-q` | Подробный журнал или только ошибки |
| `-V, --version` | Версия |

Отрицательные номера считаются с конца. Их нужно передавать через `=`:
`--base=-1`, `--page-start=-1=1`.

Коды выхода: `0` — успех, `1` — ошибка склейки, `2` — некорректные аргументы.

## Ограничения
- Примечания Word (comments) у присоединяемых документов не переносятся.
- Диаграммы, OLE-объекты, SmartArt, встроенные шрифты и VBA присоединяемых документов
  не переносятся. Каждый такой случай отмечается предупреждением в журнале.
  Изображения переносятся всегда.
- Настройки документа (`settings.xml`), тема и свойства пакета берутся из главного
  документа. Например, «различать колонтитулы чётных и нечётных страниц».
- Если у раздела нет своих колонтитулов, Word показывает колонтитулы предыдущего раздела.
  Это поведение Word, а не библиотеки. Оно заметно при `keep_headers_footers=False`
  и у документов без колонтитулов.
- В режиме `base` списки, которые используют стили со встроенной нумерацией
  (например, «List Number»), продолжают нумерацию главного документа, как при вставке в Word.
- Поля (оглавление, PAGE, NUMPAGES) Word пересчитывает при открытии или по F9.
